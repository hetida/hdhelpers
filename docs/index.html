hdhelpers¶

Introduction¶

hdhelpers is a package designed for and included in the standard installation of the hetida designer.

It contains functions that streamline plotting components, especially those that are used in the hetida platform, by

  • accessing metadata of series, singletsframes and multitsframes that complies with the hetida designer metadata conventions,

  • aditional helper functions like adjusting the timezone of timestamps, series, and dataframes,

  • accessing metadata that the hetida platform writes into the hetida designer’s plot_target_settings context variable (tbd),

  • providing toggleable standardized styling options and json serialization for plotly plots (tbd).

Functions¶

metadata¶

The examples below use Shared data setup. See Metadata examples for the return shapes and shared examples of the related getters. See Metadata lookup basics for metric selection and missing-field behavior.

Access to the metadata of SERIES, SINGLETSFRAMEs and MULTITSFRAMEs

The metadata follows the hetida designer metadata conventions, see hdhelpers.metadata.conventions for its models. read_metadata gives the metadata of an object as model, whose methods resolve the fallbacks of the conventions. The get_* functions are thin wrappers over these methods.

class hdhelpers.metadata.Recording(recording_mode: str | None = None, data_frequency: str | None = None, data_frequency_offset: str | None = None, data_frequency_timezone: str | None = None, recording_aggregation_method: str | None = None)[source]¶

Bases: object

Immutable recording settings for a metric: mode, frequency and interval alignment.

Metadata lookups use dataset frequency settings when the metric provides none. Recording modes describe when values are recorded:

  • periodic: one value per interval, timestamped at its start. Missing values are gaps.

  • on_change: record changes exceeding the value dimension’s deadband. A value holds until the next one, provided the heartbeat interval is not exceeded.

  • irregular: values at arbitrary points in time.

recording_mode¶

One of the modes above; None if unknown.

Type:

str | None

data_frequency¶

Pandas offset alias or timedelta string, e.g. “15min” or “1MS”. For on_change, the maximum time between recordings (heartbeat), even without a change. None if unknown.

Type:

str | None

data_frequency_offset¶

Shift of the frequency intervals as a timedelta string, e.g. “5min”. None means zero when a frequency is set.

Type:

str | None

data_frequency_timezone¶

Time zone for aligning frequency intervals, e.g. “Europe/Berlin”. None means UTC when a frequency is set.

Type:

str | None

recording_aggregation_method¶

For periodic values, how each interval is aggregated, e.g. “MEAN” or “MAX”. None for samples taken at the timestamp.

Type:

str | None

data_frequency_offset and data_frequency_timezone belong to data_frequency: They are None if no data_frequency applies.

hdhelpers.metadata.attach_metadata(obj: Series | DataFrame, data_type: Literal['SERIES', 'SINGLETSFRAME', 'MULTITSFRAME'] | None = None) → SeriesMetadata | SingleTSFrameMetadata | MultiTSFrameMetadata | None[source]¶

Parse metadata in attrs and attach the resulting immutable model.

Replace convention fields with attrs[“hd_metadata”]; preserve other attrs. An already attached model is returned unchanged.

Parameters:

  • obj – Series or DataFrame to update in place.

  • data_type – Convention for raw attrs, or None to infer it; see Automatic metadata type selection. Used only when no model is attached.

Returns:

SeriesMetadata | SingleTSFrameMetadata | MultiTSFrameMetadata | None – Attached model, or None for absent/invalid metadata. Failure leaves attrs unchanged.

Code example:

Using Shared data setup, attach a model while preserving unrelated attrs:

>>> data = series.copy()
>>> data.attrs["source"] = "example"
>>> meta = md.attach_metadata(data)
>>> meta.unit()
'm'
>>> sorted(data.attrs)
['hd_metadata', 'source']
>>> md.read_metadata(data) is meta
True
>>> md.attach_metadata(data) is meta
True
>>> md.attach_metadata(pd.Series([1.0])) is None
True
hdhelpers.metadata.attrs_to_json(attrs: Mapping[Any, Any]) → dict[Any, Any][source]¶

Replace attached metadata with its JSON fields in a new attrs dictionary.

Keep unrelated attrs as-is. Omit optional metadata fields set to None or their defaults.

Parameters:

attrs – Pandas attrs mapping; left unchanged.

Returns:

dict[Any, Any] – Dictionary for json.dumps or export. Unrelated attrs must also be JSON-compatible.

Code example:

Using Shared data setup, convert attached models to JSON-compatible dictionaries. This function returns a dictionary; json.dumps produces the JSON string:

>>> import json
>>> data = series.copy()
>>> _ = md.attach_metadata(data)
>>> attrs = md.attrs_to_json(data.attrs)
>>> isinstance(attrs, dict), "hd_metadata" in attrs
(True, False)
>>> encoded = json.dumps(attrs)
>>> json.loads(encoded)["metrics"][0]["value_dimensions"][0]["unit"]
'm'
>>> export = data.copy()
>>> export.attrs = md.attrs_to_json(export.attrs)
>>> "hd_metadata" in data.attrs, "hd_metadata" in export.attrs
(True, False)

The export copy can now be written with export.to_frame().to_parquet("series.parquet") if a pandas Parquet engine is installed. The original keeps its attached model.

hdhelpers.metadata.check_metadata_conventions(obj: Series | DataFrame | Mapping[str, Any], data_type: Literal['SERIES', 'SINGLETSFRAME', 'MULTITSFRAME'] | None = None) → list[MetadataConventionIssue][source]¶

Report metadata errors and warnings, optionally checking against pandas data.

For pandas inputs, also check metric IDs, value columns and time bounds. An empty list means no issues; warnings alone do not make metadata invalid.

Parameters:

  • obj – Series/DataFrame to check, or a mapping containing metadata.

  • data_type – Convention to check; required for mappings. None infers it from pandas input; see Automatic metadata type selection.

Returns:

list[MetadataConventionIssue] – Issues with severity, location and message. Invalid metadata is reported as issues.

Raises:

ValueError – A metadata mapping is provided without data_type.

Code example:

Using Shared data setup, validate the data and its metadata together, or pass plain metadata with an explicit data type. Issues describe the severity, location and cause:

>>> md.check_metadata_conventions(series)
[]
>>> md.check_metadata_conventions(series.attrs, "SERIES")
[]
>>> invalid = series.copy()
>>> invalid.attrs["metrics"][0]["default_timezone"] = "Mars/Base"
>>> issues = md.check_metadata_conventions(invalid)
>>> [(issue.severity.value, issue.location) for issue in issues]
[('error', 'metrics[0].default_timezone')]
>>> print(issues[0].message)
"Mars/Base" is neither an IANA time zone name like "Europe/Berlin" nor a UTC offset...

Read metadata as a model without changing the input.

Reuse an attached model; otherwise parse convention fields in attrs.

Parameters:

  • obj – Series or DataFrame to read.

  • data_type – Expected convention. None keeps an attached model’s type or infers it for raw attrs; see Automatic metadata type selection.

  • required – If True, raise on missing, invalid or wrong-type metadata instead of returning None.

Returns:

SeriesMetadata | SingleTSFrameMetadata | MultiTSFrameMetadata | None – Attached or newly parsed model; None for missing, invalid or wrong-type metadata.

Raises:

MetadataConventionError – Metadata cannot be returned and required=True.

Code example:

Using Shared data setup, read a model without changing the original attrs:

>>> meta = md.read_metadata(series, required=True)
>>> meta.unit()
'm'
>>> "hd_metadata" in series.attrs
False
>>> missing = pd.Series([1.0])
>>> md.read_metadata(missing) is None
True
>>> try:
...     md.read_metadata(missing, required=True)
... except md.MetadataConventionError as error:
...     print(error.issues[0].message)
No metadata in attrs.

Attach the supplied metadata model to a result object.

Store it under attrs[“hd_metadata”], replacing convention fields and preserving unrelated attrs.

Parameters:

  • obj – Result Series or DataFrame created by your component; updated in place.

  • meta – Validated metadata model; shared without copying or revalidation.

None – Updates obj in place.

Code example:

Convert the metre values from Shared data setup to centimetres and set matching metadata on the result. The original metadata stays unchanged:

>>> meta = md.read_metadata(series, required=True)
>>> result = series * 100
>>> changed = meta.with_value_dimension(None, "value", unit="cm")
>>> md.set_metadata(result, changed)
>>> md.get_series_unit(result), md.get_series_unit(series)
('cm', 'm')
>>> md.read_metadata(result) is changed
True

hdhelpers.helpers.modify_timezone(object_to_convert: T, to_timezone: str | None = None, column_names: list[str] | None = None, convert_index: bool = True) → T[source]¶

Convert aware timestamps or localize naive timestamps to the selected time zone.

Parameters:

  • object_to_convert (pd.Timestamp | datetime.datetime | pd.Series | pd.DataFrame) – Timestamp, datetime, Series or DataFrame to convert.

  • to_timezone – Target zone, e.g. “Europe/Berlin”. None uses the plot target setting; if unset, naive values use UTC and aware values keep their zone.

  • column_names – Columns to convert. None/[] selects the Series index or DataFrame “timestamp” column. For Series values, pass [series.name]. Ignored for scalars.

  • convert_index – Also convert the pandas index. With column_names=None/[], a Series index is always converted. Ignored for scalars.

Returns:

pd.Timestamp | pd.Series | pd.DataFrame – Timestamp for scalar inputs; converted copy for nonempty pandas inputs. Empty pandas inputs are returned unchanged.

Raises:

  • TypeError – Unsupported input or incompatible timestamp/index values.

  • ValueError – Unknown time zone or invalid datetime values.

  • KeyError – A requested column is absent.

Code example:

>>> from hdhelpers.helpers import modify_timezone
>>> modified_timezone = modify_timezone(pd.to_datetime("2025-01-01T01:00:00+05:00"), to_timezone="Europe/Berlin")
>>> int(modified_timezone.utcoffset().total_seconds())
3600
